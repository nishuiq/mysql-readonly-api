= SQL 查询条例

本文记录用户提交 SQL 时的规则、执行位置和边界。启动、配置和接口用法见 link:../README.adoc[README.adoc]。

这些规则约束调用方提交的 SQL。服务内部为 schemas、tables、ddl 等接口构造的查询，以及 MySQL 返回的结果文本，不受用户 SQL 的分号和注释规则限制。

== 请求与 SQL

. *一条请求，一条 SQL。* 连接不启用 `CLIENT_MULTI_STATEMENTS`，MySQL 协议阻止一次执行多条语句；SQL 门栏也拒绝语句分号。多个 HTTP 请求仍可并发。参考 https://dev.mysql.com/doc/c-api/8.0/en/c-api-multiple-queries.html[MySQL 多语句支持]。
. *禁止语句分号。* 执行前拒绝作为语句分隔符或末尾终止符的 `;`；字符串和引用标识符中的分号属于内容，不参与拦截。
. *禁止注释。* 执行前拒绝实际 SQL 注释，包括 `#`、`-- `、`/* ... */`、MySQL 可执行注释 `/*! ... */` 和优化器 hint `/*+ ... */`。字符串或引用标识符中的相同字符不视为注释。参考 https://dev.mysql.com/doc/refman/8.0/en/comments.html[MySQL 注释语法]。
. *只允许只读查询。* 用户 SQL 只允许 SELECT、WITH、SHOW 和针对 SELECT/WITH 的 EXPLAIN；MySQL 5.7 不支持 CTE，具体语法由对应版本的 MySQL 判断。EXPLAIN ANALYZE 会实际执行目标语句，因此始终拒绝。
. *禁止写入和事务控制。* SQL 门栏拒绝写入、结构变更、CALL、SET、事务控制、锁定读、`SELECT ... INTO` 和用户变量；允许读取 `@@` 系统变量。`INSERT()`、`REPLACE()` 等同名读取函数不因名称与写入关键字相同而拒绝。
. *禁止危险函数。* SQL 门栏拒绝 `LOAD_FILE()`、`SLEEP()`、`BENCHMARK()`、用户锁函数以及 GTID 或复制位置等待函数。数据库账号仍需限制存储函数和其他扩展的授权，SQL 文本不能反映所有函数副作用。
. *检查 SQL，按需追加分页。* SELECT/WITH 和 EXPLAIN 使用 SQLGlot MySQL 语法树及词法结果交叉检查最外层 LIMIT；SHOW 使用词法检查并由 MySQL 判断语法。解析失败或最外层 LIMIT 无法确认时拒绝。SELECT/WITH 没有最外层 LIMIT 时在原文末尾追加接口分页；已有 LIMIT、SHOW 和 EXPLAIN 保持原文，不添加外层派生表、COUNT 或 EXPLAIN。
. *最外层 LIMIT 不超过 5000。* SQL 中显式指定的最外层 LIMIT 行数超过 5000 时拒绝，偏移值和子查询的 LIMIT 不参与该上限检查。`LIMIT 6000, 20` 的行数是 20，`LIMIT 20, 6000` 的行数是 6000。
. *不修改数据库 SQL mode。* 既有词法检查继续使用连接读取到的模式判断字符串、标识符和注释边界，SQLGlot 使用 MySQL 方言；词法结果和语法树对最外层 LIMIT 不一致时拒绝。禁止多语句依靠连接层，不为此修改数据库模式。

== 数据库与连接

. *数据库事务保持只读。* 新建物理连接时执行 `SET SESSION TRANSACTION READ ONLY`；用户不能提交 SET，但服务内部按配置初始化只读事务、时区和超时。只读账号按任务授予必要的读取权限；只读事务不能阻止所有函数副作用或资源消耗。
. *请求结束时结束事务并归还连接。* 当前 PyMySQL 连接未启用自动提交，SQLAlchemy 关闭 Session 时回滚尚未结束的事务并释放连接，避免遗留事务快照和元数据锁。回滚不会自动恢复会话系统变量，也不保证清理所有连接级状态。参考 https://docs.sqlalchemy.org/en/20/core/pooling.html[SQLAlchemy 连接池] 和 https://dev.mysql.com/doc/refman/8.0/en/metadata-locking.html[MySQL 元数据锁]。
. *固定功能保留内部查询。* schemas、tables、ddl 等接口继续使用服务构造的 SQL、绑定参数和必要的结果限制，不受用户 SQL 输入规则影响。

== 结果与资源

. *返回行数有硬上限。* `query.limit` 显式配置为 1–5000；请求省略 `limit` 时使用该值，请求只能缩小该值。`offset` 为非负整数，默认 0，作用于原 SQL 结果。
. *查询不修改会话行数限制。* 未指定最外层 LIMIT 的 SELECT/WITH 追加 `LIMIT <limit + 1> OFFSET <offset>`；已有 LIMIT 时保留原 SQL。服务不读取、设置或恢复 `sql_select_limit`。
. *偏移和截断依据原查询结果。* 已有最外层 LIMIT 的查询、SHOW 和 EXPLAIN 使用流式游标跳过 `offset`，再读取至多 `limit + 1` 行；其他 SELECT/WITH 由追加的 SQL OFFSET 完成跳过。有额外行时返回前 `limit` 行并标记截断；SQL 自己的 LIMIT 仍然有效，未截断不代表底层表已经读完。
. *行数限制不等于资源限制。* 偏移较大时数据库可能需要处理和传输大量被跳过的行；SHOW、EXPLAIN 等语句不一定遵循会话行数限制，关闭游标也可能继续接收未消费的结果。查询仍可能扫描或排序大量数据，字段大小也不受行数限制。

== 输入示例

下表每行是一条独立请求。

[cols="4,2,5",options="header"]
|===
|SQL 输入 |判定 |原因

|`SELECT 1` |允许 |单条只读查询
|`SELECT 1;` |拒绝 |包含语句分号
|`SELECT 'a;b'` |允许 |分号位于字符串中
|`SELECT '# data'` |允许 |`#` 位于字符串中
|`SELECT 'SET'` |允许 |`SET` 位于字符串中
|`SELECT 1 -- note` |拒绝 |包含注释
|`SELECT 1 /*!50000 + SLEEP(1) */` |拒绝 |包含可执行注释
|`SET SESSION TRANSACTION READ WRITE` |拒绝 |调用方不能修改事务访问模式
|`SELECT * FROM app.orders FOR UPDATE` |拒绝 |锁定读
|`SELECT * FROM app.orders LIMIT 5001` |拒绝 |最外层 LIMIT 超过 5000
|`SELECT COUNT(*) FROM app.orders` |允许 |调用方自行编写计数 SQL
|`EXPLAIN SELECT * FROM app.orders` |允许 |调用方自行编写执行计划 SQL
|`EXPLAIN ANALYZE SELECT * FROM app.orders` |拒绝 |执行型计划被禁止
|===

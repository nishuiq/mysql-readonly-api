= mysql-readonly-api

供 AI skill 调用的 MySQL 只读 REST API，支持多个 profile 和 MySQL 5.7（GA 版本）、8.x。

== 启动与配置

需要 uv；项目要求 Python 3.15+，`.python-version` 将默认解释器固定为 3.15：

[source,powershell]
----
uv python install
uv sync
Copy-Item config.example.toml config.toml
# 编辑 config.toml，填写数据库连接并启用 profile
uv run main.py
----

`uv python install` 按 `.python-version` 安装解释器，`uv sync` 创建或更新项目的 `.venv`。配置采用 TOML 1.1，由 Python 3.15 标准库 `tomllib` 读取，支持多行嵌套内联表。

完整字段、示例值和对齐的逐字段注释见 link:config.example.toml[config.example.toml]。所有配置字段必须显式填写，禁用的 profile 也需完整配置；缺项、未知字段、类型或范围错误会在启动时报出字段路径，不自动补值。

配置文件固定为工作目录下的 `config.toml`，程序不自动转换或回退读取其他格式。TOML 没有 `null`，`ssl_ca = ""` 显式表示不指定 CA 文件，内部转换为 `None`；单独的 `[profiles]` 空表表示不配置任何环境。本地 `config.toml` 不提交。

每个 profile 使用 `[profiles.环境名]` 小节，连接和连接池配置在其 `mysql = { ... }` 中嵌套填写。多行内联表的字段以逗号分隔，允许尾逗号；Windows 路径可用单引号保留反斜杠，例如 `ssl_ca = 'D:\certs\mysql-ca.pem'`。

配置校验后形成不可变快照，运行期间不能增删、替换或修改 profile。修改配置文件后需重启服务才能生效。

每个启用的 profile 有独立的惰性连接池。数据库请求在 URL 中指定 profile，SQL 使用 `schema.table`；没有默认 schema，不能跨 profile 联表。

=== 连接与只读边界

示例仅监听本机，*不提供 HTTP 身份认证*。数据库账号应仅授予任务需要的读取权限。

TLS 开启时要求连接实际加密，并校验证书和主机名。`ssl_ca = ""` 使用系统信任库，自签名证书需填写可信 CA 文件路径；非 TLS 连接使用 `use_ssl = false` 和 `ssl_ca = ""`。

通过 SSH 转发时，MySQL 端口填写本地转发端口，连接主机名仍需通过证书校验；REST 服务使用独立的监听端口。

新物理连接设置 `SET SESSION TRANSACTION READ ONLY`，请求结束时回滚事务。SQL 检查和只读会话不能替代账号权限：MySQL 只读事务仍允许修改临时表，存储函数的能力也取决于数据库端定义和授权。

=== 超时

[cols="2,3",options="header"]
|===
|配置 |作用

|`query.timeout_ms` |MySQL `max_execution_time`，单位为毫秒，主要限制只读 SELECT
|`mysql.connect_timeout` |建立数据库连接的超时，单位为秒
|`mysql.io_timeout` |网络发送 SQL 与接收结果的超时，单位为秒，同时控制驱动读写超时
|`mysql.pool.timeout` |连接池用满后等待可用连接的超时，单位为秒
|`mysql.pool.recycle` |连接存续多久后在再次取用时回收，单位为秒，不是查询超时
|===

`max_execution_time` 不覆盖所有 SHOW、元数据工作或存储程序。`io_timeout` 不是请求总时限，网络超时也不保证数据库任务同时取消。

== 接口

[cols="3,3,2",options="header"]
|===
|方法与路径 |参数或请求体 |结果

|`GET /profiles` |无 |已启用的 profile 名称和描述
|`GET /profiles/<profile>/schemas` |`limit` 可选 |账号可见的非系统 schema
|`GET /profiles/<profile>/tables` |`schema` 必填；`keyword`、`limit` 可选 |表或视图的名称、类型、注释和估计行数
|`GET /profiles/<profile>/ddl` |`schema`、`table` 必填 |紧凑结构摘要
|`POST /profiles/<profile>/query` |SELECT/WITH/SHOW/EXPLAIN；`limit`、`offset` 可选 |查询、计数或执行计划结果
|===

POST 请求体直接使用 UTF-8 `text/plain` SQL，查询参数需 URL 编码。`/profiles/<profile>/ddl` 固定返回纯文本，其余接口支持 `format=tsv`（默认）和 `format=json`。

`keyword` 对表名和注释做包含匹配，保留 `%`、`_` 等 LIKE 通配符。`table` 支持重复参数或逗号分隔；含逗号的名称需用反引号包裹，名称内的反引号写成两个反引号。

=== 行数与偏移

`query.limit` 必须显式配置为 1–5000，示例值为 5000。请求的 `limit` 必须为正整数，省略时使用 `query.limit`，请求只能缩小该值。例如配置为 5000 时，`limit=20` 返回至多 20 行，`limit=5001` 被拒绝。行数限制不限制单个字段大小，需要控制响应体积时应选择所需列或在 SQL 中截取字段。

`offset` 为非负整数，默认 0，表示从原 SQL 结果中跳过的行数，适用于 SELECT/WITH、SHOW 和 EXPLAIN。分页与截断语义见下文。

=== 调用示例

[source,powershell]
----
$base = "http://127.0.0.1:8765"
Invoke-RestMethod "$base/profiles?format=tsv"
$sql = "SELECT id, name FROM example_app.orders ORDER BY id LIMIT 20"
Invoke-RestMethod -Method Post -Uri "$base/profiles/example-dev/query?format=tsv&limit=20" -ContentType "text/plain; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($sql))
----

== 结果格式

常规浏览和查询优先使用 TSV；可省略 `format`，或显式指定 `format=tsv`。需要程序化处理行列、提取源码原文或区分 SQL NULL 与字符串 `"NULL"` 时使用 `format=json`。

TSV 响应的 Content-Type 为 `text/tab-separated-values; charset=utf-8`。结果先显示列名，再以 tab 分隔字段、LF 分隔记录；字段内的 CR、LF、tab 和反斜杠保持原值。SQL NULL 与字符串 `"NULL"` 都显示为 `NULL`，因此不能仅按 tab 和换行可靠还原所有字段。

结果截断时，TSV 在表头前增加独立的 `[truncated]` 行，不插入空行：

[listing]
----
[truncated]
id	body
1	Alice
2	NULL
----

对应的 JSON 用二维数组表示数据行，并显式标记截断：

[source,json]
----
{"columns":["id","body"],"rows":[[1,"Alice"],[2,null]],"truncated":true}
----

空结果返回 200，TSV 只有表头，JSON 为 `rows:[]`。JSON 按标准解码即可，不手工替换转义序列。

[cols="2,2,3",options="header"]
|===
|数据类型 |TSV |JSON

|字符串、整数、浮点数 |驱动值的文本表示 |字符串、number
|DECIMAL |保留精度和小数位 |字符串
|DATE / DATETIME / TIMESTAMP |日期时间文本 |同样的字符串；TIMESTAMP 按会话时区返回
|TIME |`[-]HH:MM:SS[.ffffff]`，可超过 24 小时 |同样的字符串
|二进制（包括 BIT） |`0x...` |`{"hex":"..."}`
|SQL NULL |`NULL` |`null`
|===

JSON 保留字段边界，但不提供完整 MySQL 类型信息；MySQL JSON 字段仍为字符串，需要时再解码。JavaScript 大整数精度需要由调用方处理，例如在 SQL 中 CAST 为 CHAR。`use_unicode: false` 使字符字段按 bytes 使用二进制约定。

== SQL 与分页

查询规则和执行边界见 link:docs/sql-query-rules.adoc[SQL 查询条例]。

每次只接受一条 SELECT、WITH、SHOW 或 EXPLAIN 语句，拒绝语句分号和 SQL 注释，包括可执行注释与优化器 hint；字符串或引用标识符中的相同字符不受影响。拒绝写操作、CALL/SET、用户变量、锁定读、文件/等待/锁函数和 EXPLAIN ANALYZE，允许 `@@` 系统变量读取。

词法检查沿用连接的 `sql_mode`，SQLGlot 检查 SELECT/WITH 和 EXPLAIN 的语法树；SHOW 使用词法检查并由 MySQL 判断语法。`INSERT()`、`REPLACE()` 字符串函数可用。MySQL 5.7 不支持 WITH/CTE。

=== 查询与分页

服务不为用户查询添加外层派生表、COUNT 或 EXPLAIN。SELECT/WITH 没有最外层 LIMIT 时，服务在原 SQL 末尾追加 `LIMIT <limit + 1> OFFSET <offset>`；已有最外层 LIMIT 时保留原文，行数超过 5000 则拒绝。SQL 自己的偏移量和子查询中的 LIMIT 不受这个检查限制。

例如 `LIMIT 6000, 20` 的行数是 20，允许执行；`LIMIT 20, 6000` 的行数是 6000，会被拒绝。SQL 自带的 LIMIT 先作用于原查询结果，API 再跳过 `offset` 行，最多返回 `limit` 行；结果中有额外一行时标记截断。

服务不为查询设置或恢复 `sql_select_limit`。SHOW 和 EXPLAIN 不追加 LIMIT，结果可能受数据库已有的会话设置影响。

已有最外层 LIMIT 的查询、SHOW 和 EXPLAIN 使用流式游标跳过 API `offset`；没有最外层 LIMIT 的 SELECT/WITH 由追加的 SQL OFFSET 处理。偏移越大，数据库可能需要处理更多行；流式跳过还会传输这些行，关闭游标时驱动也可能继续读取尚未消费的结果。需要高效翻页时，优先按唯一稳定的键在 SQL 中筛选。

重复的输出列名可按原 SQL 返回，JSON 的 `columns` 和 `rows` 分别保留列顺序。原 SQL 的 LIMIT 仍然生效，截断标志不会越过它探测底层表；返回 `truncated:false` 不代表底层表已读完。

需要稳定顺序时，在原 SQL 中使用唯一的 ORDER BY。多次请求不共享快照，数据变化时偏移分页可能重复或遗漏。

计数和执行计划通过同一个查询接口自行编写，例如 `SELECT COUNT(*) FROM example_app.orders` 和 `EXPLAIN SELECT * FROM example_app.orders`。仅在需要总数时计数，计数可能昂贵；API 分页不会预先 COUNT。

大量、可分页的元数据应查询 `information_schema`；schemas/tables 截断时也可缩小筛选范围或改用此方式。

== DDL 与原生定义

`/profiles/<profile>/ddl` 展示字段、默认值、生成列、主键/索引、外键和表属性。8.x 按版本补充表达式索引、索引可见性和实际存储的 CHECK 约束，5.7 不查询这些专属字段。

摘要不适合备份或迁移：省略普通整数显示宽度但保留 ZEROFILL，不区分显式 DEFAULT NULL 与未指定默认值，也不完整重建分区、表空间和全部引擎选项。字符串引用遵循会话 `sql_mode`。

完整原生定义通过 `/profiles/<profile>/query` 执行 `SHOW CREATE TABLE schema.name` 获取，其他对象使用 VIEW、PROCEDURE、FUNCTION 或 EVENT 替换 TABLE。

视图源码可见时，`/profiles/<profile>/ddl` 使用原生 SHOW CREATE VIEW；仅权限不足时返回 `missing source code`，其他错误正常上报。NULL 过程或函数源码也表示当前账号不可见，不能当成空定义。

查询通常需要 SELECT，视图源码需要 SHOW VIEW；过程、函数和事件源码按版本与账号身份决定可见性。5.7 没有 SHOW_ROUTINE，8.0.20+ 才提供此权限；不建议为读取源码授予宽泛的管理或写入权限。

== 错误处理

错误始终为纯文本，即使请求 `format=json`；先检查 HTTP 状态再解析 JSON。依据响应中的参数位置、MySQL errno 或消息定位问题，不盲目重试语法或权限错误。

[cols="1,4",options="header"]
|===
|HTTP |含义

|400 |SQL 校验、语法或 UTF-8 编码错误
|403 |权限不足或违反只读事务
|404 |未知或禁用的 profile，或对象不存在、不可见
|422 |参数错误，包括超出配置上限的 limit 和负数 offset
|503 |连接、认证、TLS 或连接池问题
|504 |查询超时或被中断
|500 |内部异常
|===

SQL 错误保留 MySQL errno 和驱动消息，不附加 SQLAlchemy 的 SQL/参数堆栈；连接错误隐藏账号、地址等细节。异常日志只记录错误类型或状态和错误号；开启 `app.sql_log` 则另行记录 SQL 与绑定参数。

== 开发与验证

[source,powershell]
----
uv run ruff check .
uv run ruff format --check .
uv run python -X utf8 -m unittest discover -s tests -v
----

集成测试默认跳过。指定**专用测试实例**的 `MYSQL_TEST_PORT` 后运行同一命令；可另设 `MYSQL_TEST_HOST`（默认 127.0.0.1）、`MYSQL_TEST_USER`（root）和 `MYSQL_TEST_PASSWORD`（空）。

测试默认使用无 TLS 本地连接，在随机命名的 `readonly_api_test_*` schema 内创建表、视图和存储对象，结束后清理；账号需有相应权限。测试不读取本地 `config.toml` 或业务 profile。

分别在 5.7 和 8.x 运行可覆盖版本差异。实例配置了可信 TLS 证书时，设置 `MYSQL_TEST_SSL_CA` 为 CA 文件路径可额外运行 TLS 连接验证。

临时环境、下载包、日志和生成文件放在已忽略的 `temp/` 下；MySQL 测试资源可集中在 `temp/mysql-integration/`，测试结束后关闭实例。
